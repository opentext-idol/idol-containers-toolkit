5. Before upgrading:

   Take a database backup. The service migrates its schema in place and refuses to start
   rather than modify a schema it cannot migrate, so an upgrade should not lose data - but
   a backup is what makes that recoverable if one goes wrong.

{{- if .Values.postgresql.enabled }}
     kubectl exec -n {{ .Release.Namespace }} {{ .Release.Name }}-postgresql-postgresql-0 -- \
       env PGPASSWORD=$(kubectl get secret -n {{ .Release.Namespace }} {{ include "idol-connector-management.postgresql.secretName" . }} -o jsonpath='{.data.password}' | base64 -d) \
       pg_dump -U {{ (include "idol-connector-management.postgresql" . | fromYaml).username }} -d {{ (include "idol-connector-management.postgresql" . | fromYaml).database }} > backup.sql
{{- else }}
     pg_dump -h {{ (include "idol-connector-management.postgresql" . | fromYaml).host }} \
       -U {{ (include "idol-connector-management.postgresql" . | fromYaml).username }} \
       -d {{ (include "idol-connector-management.postgresql" . | fromYaml).database }} > backup.sql
{{- end }}

6. Cleaning up after `helm uninstall`:
{{- if not $ownsPvcs }}

   This release provisions no PersistentVolumeClaims of its own - the database is
   external and no volume-backed component is enabled - so `helm uninstall` removes
   everything it created.
{{- if .Values.connectorManagement.resourcesVolume.existingClaim }}
   Your claim {{ .Values.connectorManagement.resourcesVolume.existingClaim }} was never owned by the release and is untouched.
{{- end }}
   Its data lives in the external database, which the chart never touches.
{{- else }}

   `helm uninstall` does NOT remove this release's PersistentVolumeClaims. They are
   created by the StatefulSet controller rather than by Helm, and StatefulSets default
   to persistentVolumeClaimRetentionPolicy Retain, so they and their data survive:

{{- if .Values.postgresql.enabled }}
     - connector/target/job state:  data-{{ .Release.Name }}-postgresql-postgresql-N
{{- end }}
{{- if .Values.nifi.enabled }}
     - NiFi flow + repositories:    nifi-data-{{ $nifiFullname }}-0
{{- end }}
{{- if and .Values.connectorManagement.resourcesVolume.enabled (not .Values.connectorManagement.resourcesVolume.existingClaim) }}
     - connector resources:         resources-{{ $fullname }}-0
{{- end }}
{{- if and .Values.documentsecurity.enabled .Values.documentsecurity.postgresql.enabled }}
     - documentsecurity database:   data-{{ include "idol-connector-management.documentsecurity.postgresql.fullname" . }}-postgresql-N
{{- end }}
{{- if .Values.connectorManagement.resourcesVolume.existingClaim }}

   Your claim {{ .Values.connectorManagement.resourcesVolume.existingClaim }} is untouched by any of this - it was never
   owned by the release.
{{- end }}

   That is deliberate: it lets you reinstall onto the existing data. It also means a
   reinstall inherits the old state, and that anything retained for the same reason
   (credentials tied to that data) stays too.

   To discard the release completely - THIS PERMANENTLY DESTROYS ALL CONNECTOR STATE:

     kubectl delete pvc,secret -l app.kubernetes.io/instance={{ .Release.Name }} -n {{ .Release.Namespace }}

   That selector covers the sub-charts' databases too - every PVC in the release
   carries app.kubernetes.io/instance, whether from its volumeClaimTemplate labels or
   copied from the StatefulSet selector by the controller.

   Then check for PersistentVolumes left behind. With a StorageClass whose
   reclaimPolicy is Delete they go automatically; with Retain they stay in status
   Released and must be removed by hand:

     kubectl get pv | grep {{ .Release.Namespace }}
{{- end }}

{{- end }}
